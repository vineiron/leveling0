# Database

leveling0 stores signed-in user quests in Postgres. Anonymous quests are stored
only in browser `localStorage`.

## Connection Model

The app has one database connection purpose today:

- **Runtime app connection**: `DATABASE_URL`

For serverless production deploys, `DATABASE_URL` should use a Supabase
transaction pooler URL when applicable. The `postgres-js` client is configured
with `{ prepare: false }`, which is compatible with transaction pooling.

Drizzle generation and migrations currently also use `DATABASE_URL` from
`drizzle.config.ts`. Use a direct or session-pooler connection for migration
commands when possible.

## Schema Source

The Drizzle schema lives in:

```text
src/db/schema.ts
```

Generated SQL migrations live in:

```text
drizzle/
```

Current migrations:

- `0000_items.sql`
- `0001_rename_items_to_quests.sql`

## Tables

### `quests`

Stores signed-in, user-owned quest records.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` | Primary key, generated by the database. |
| `user_id` | `uuid` | Supabase `auth.users.id`; no local profile table. |
| `status` | `quest_status` | Board column: `backlog`, `in_progress`, or `done`. |
| `position` | `integer` | Sort position within the column. |
| `title` | `text` | Required quest title. |
| `due_at` | `timestamptz` | Optional due date. |
| `tags` | `text[]` | Quest tags. Defaults to an empty array. |
| `detail` | `text` | Required markdown detail body. |
| `note` | `text` | Optional private markdown note. |
| `created_at` | `timestamptz` | Creation timestamp. |
| `updated_at` | `timestamptz` | Updated by app writes. |

Indexes:

- `quests_user_status_position_idx` on `user_id, status, position`

### `quest_status`

Postgres enum used by `quests.status`:

- `backlog`
- `in_progress`
- `done`

## Ownership And Authorization

`user_id` stores the Supabase authenticated user id directly.

Private reads and writes must include the authenticated user id, for example:

```text
where quests.id = questId
  and quests.user_id = userId
```

The app uses Drizzle with a direct Postgres connection, so Supabase Row Level
Security is not the runtime authorization boundary. RLS may be added later as
defense-in-depth, but application-level owner checks remain required.

## Validation Limits

Server-side validation currently enforces:

- title length: 1 to 200 characters
- detail length: 1 to 20,000 characters
- note length: up to 10,000 characters
- tag length: 1 to 32 characters
- tags per quest: up to 15
- reorder IDs per status group: up to 1,000

These limits protect request handling, database writes, and browser rendering.

## Migration Workflow

After changing `src/db/schema.ts`, generate and review a migration:

```bash
pnpm drizzle-kit generate --name=your_change_name
```

Then apply it:

```bash
pnpm drizzle-kit migrate
```

Review generated SQL before applying it.
